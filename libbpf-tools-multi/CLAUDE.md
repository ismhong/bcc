## Repository Context

This directory (`libbpf-tools-multi/`) is part of a [iovisor/bcc](https://github.com/iovisor/bcc) fork that focuses on the **libbpf-based CO-RE (CO-RE-Relocation)** tools from `libbpf-tools/`. The fork adds:

- **`libbpf-tools-multi/`** — a Busybox-style multi-call binary that aggregates all ~91 libbpf-tools into a single static binary (`libbpf-tools-box`)
- Docker cross-build infrastructure for arm64/x86_64
- Many new tools not present in upstream bcc (cpuidle, cputop, forksnoop, tcpwin, etc.)
- RTK-specific additions (rtkheaptop, whoentercritical, smclatency, etc.)

The parent `libbpf-tools/` directory contains individual tools that are the source of truth — this directory never modifies files there.

## Build Commands

```bash
# 1. Build libbpf-tools first (generates libbpf.a, .skel.h headers)
make -C ../libbpf-tools

# 2. Build the multi-call binary
make

# 3. Verify link — count _main symbols (should match tool count)
make verify

# 4. Cross-compile
make -C ../libbpf-tools ARCH=arm64 CROSS_COMPILE=aarch64-linux-gnu-
make ARCH=arm64 CROSS_COMPILE=aarch64-linux-gnu-

# 5. Clean
make clean
```

## Full CI Build (Docker multi-arch)

```bash
# Builds for arm64 + x86_64 via Docker buildx, strips binaries, applies UPX
# Docker image is auto-skipped if already present (cached locally)
./build-all.sh

# Force rebuild Docker images (e.g. after Dockerfile change):
./build-all.sh --rebuild

# Show help:
./build-all.sh -h
```

## Architecture

### Multi-Call Binary Approach (`libbpf-tools-box`)

Tools in `libbpf-tools/` cannot be linked directly together because many define conflicting non-static global symbols (e.g. `argp_program_version`, `handle_event`, `main`).

**Solution**: Auto-generated wrapper `.c` files rename conflicting symbols via `#define` before `#include`-ing the original tool source:

```
.output/wrappers/<toolname>.c   (auto-generated, gitignored)
  └─ #define main → <toolname>_main
  └─ #define handle_event → <toolname>_handle_event
  └─ #include "../libbpf-tools/<toolname>.c"
```

### Key Files

| File | Purpose |
|---|---|
| `Makefile` | Build system — generates wrappers, compiles, links |
| `dispatch.c` | `main()` entry — routes by argv[0] (symlink) or argv[1] (direct) |
| `libbpf-tools-box` | Output binary (gitignored) |
| `.output/wrappers/` | Auto-generated wrapper `.c` files (gitignored) |
| `.output/*.o` | Compiled objects (gitignored) |

### What's Shared vs. Unique

| Component | Handling |
|---|---|
| `libbpf.a` | Linked once, shared by all tools |
| `trace_helpers.o`, `compat.o`, etc. | Compiled once from `libbpf-tools/*.c`, linked once |
| BPF skeletons (`*.skel.h`) | Embedded per-tool via wrapper object (unique per tool) |
| `argp_program_version`, `main`, etc. | Renamed per-tool via `#define` in wrapper |
| Static helpers in tool `.c` | Stay `static` — no conflict |

### Tool Source Pattern (in `../libbpf-tools/`)

Each tool has three files sharing its name:
- `<tool>.c` — user-space C code (main(), argp parsing, event handling)
- `<tool>.bpf.c` — BPF program bytecode (compiled via clang -target bpf)
- `<tool>.h` — shared header (structs, enums, constants)
- `.output/<tool>.bpf.o` — compiled BPF object
- `.output/<tool>.skel.h` — BPF skeleton header (generated by bpftool)

## Adding a New Tool

1. Add tool source files to `../libbpf-tools/` (the canonical location)
2. Add `newtool` to `TOOLS` list in `Makefile`
3. Add `extern int newtool_main(int argc, char **argv) __attribute__((weak));` to `dispatch.c`
4. Add `{ "newtool", newtool_main }` to the `tools[]` table in `dispatch.c`
5. Run `make` — wrapper is auto-generated

## If Build Fails with "multiple definition"

Upstream added a non-static global symbol that conflicts. Add a `#define` line to the wrapper generation rule in `Makefile` (the `$(WRAPPERS_DIR)/%.c` target around line 189):

```makefile
printf '#define new_symbol  %s_new_symbol\n' "$$TOOL" >> $@; \
```

No changes needed in `libbpf-tools/`.

## Dispatch Logic (`dispatch.c`)

- **Symlink invocation**: `./opensnoop` → `argv[0]` = "opensnoop" → dispatched by name
- **Direct invocation**: `./libbpf-tools-box opensnoop` → `argv[1]` = "opensnoop" → dispatched, argv shifted
- All tool functions are declared `__attribute__((weak))` so tools not compiled on a given arch resolve to NULL (no linker error)
- `--btf <path>` is parsed before dispatch (custom BTF path support)

## Docker Cross-Build

- `Dockerfile`: Alpine 3.17-based build environment with clang, llvm, elfutils
- `build-all.sh`: Orchestrates multi-arch (`linux/arm64`, `linux/amd64`) builds via Docker buildx
- `build.sh`: Runs inside the container — builds libbpf-tools, builds multi-call, strips, chowns output
- Output: `libbpf-tools-out/<arch>/{debug,stripped,upx}/`
